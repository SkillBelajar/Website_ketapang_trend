# AI Project Memory: Website_ketapang_trend

## 1. Arsitektur Proyek
- **Stack**: Docker Compose (5 services: `wp_mariadb`, `wp_redis`, `wp_wordpress` [fpm-alpine], `wp_nginx` [alpine], `wp_cloudflared` [profile tunnel]).
- **Host Port**: Default `127.0.0.1:8084` (didefinisikan di `.env` sebagai `APP_PORT`).
- **Domain Publik**: `https://ketapang.pawandigital.id/` (melalui Cloudflare Tunnel).
- **FastCGI Cache**: `tmpfs` RAM Cache 256M di `/var/cache/nginx/fastcgi` (Zero Disk I/O).
- **Object Cache**: Redis 7.2 (`redis-cache` plugin + `object-cache.php` drop-in).
- **Tema Utama**: `detik-ketapang` di `/var/www/html/wp-content/themes/detik-ketapang/` (source tracked di `./themes/detik-ketapang/`).

## 2. Perintah Penting (Cheat Sheet)
```bash
# Setup & Restore instan setelah git clone:
./setup.sh

# Status container
docker compose ps

# WP-CLI (selalu gunakan parameter konfigurasi Redis ekstra):
docker run --rm \
  --network wp-prod-stack_wp-net \
  -e WORDPRESS_DB_HOST=mariadb:3306 \
  -e WORDPRESS_DB_NAME=wordpress \
  -e WORDPRESS_DB_USER=wpuser \
  -e WORDPRESS_DB_PASSWORD=<password> \
  -e "WORDPRESS_CONFIG_EXTRA=define('WP_REDIS_HOST', 'redis'); define('WP_REDIS_PORT', 6379);" \
  -v wp-prod-stack_wp_data:/var/www/html \
  wordpress:cli <perintah-wp>

# Flush Redis Object Cache:
# (jalankan wp cache flush via WP-CLI container di atas)

# Purge FastCGI RAM Cache Nginx:
docker compose exec nginx sh -c "rm -rf /var/cache/nginx/fastcgi/*"

# Dump database terkini:
docker exec wp_mariadb mariadb-dump -u wpuser -p<password> wordpress > database/init.sql
```

## 3. Aturan & Jebakan Teknis (Pitfalls)
1. **Host tanpa PHP / Composer**: Seluruh operasi WordPress/PHP WAJIB dijalankan via container Docker (`wp_app` atau temporary `wordpress:cli`).
2. **Reverse Proxy & HTTPS**: Nginx meneruskan `X-Forwarded-Proto` dan `X-Forwarded-Port`. Jangan paksakan `forceScheme` di PHP jika meracuni loopback; biarkan deteksi protokol otomatis bekerja.
3. **Database URL Search-Replace**: Jika port lokal atau domain berubah, jalankan `wp search-replace "OLD_URL" "NEW_URL"` di semua tabel database, lalu flush Redis dan Nginx cache.
4. **Proteksi xmlrpc.php**: Endpoint `/xmlrpc.php` sudah diblokir di level Nginx (`403 Forbidden`).
